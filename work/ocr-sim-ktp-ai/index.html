Context

OCR pre-fills identity fields in KYC. Its quality directly affects user effort (manual corrections) and completion reliability.

Problem

  • Existing OCR was expensive at scale (~Rp120/hit).
  • Users often had to correct extracted fields (high edit rate).
  • SIM coverage was a critical gap.

Approach

Edit rate: % of extracted fields that users edited before submission. Lower is better (less friction).

I benchmarked options across quality (edit rate), cost (Rp/hit), and coverage (SIM/KTP support).

Evidence

Decision

We chose Vertex AI as the primary OCR engine because it was significantly cheaper, reduced correction effort, and enabled SIM coverage.

Monitoring plan

  • Edit rate trend (overall and per-field)
  • Failure/timeout rate and latency distribution
  • Downstream KYC completion changes after rollout

Learnings

  • OCR “quality” should be measured in user correction cost, not vendor claims.
  • Cheaper + better needs monitoring so it stays true in production.
